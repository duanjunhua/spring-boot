## 持久化实体
### Pulsar相关对象
租户（`Tenant`）、集群（`cluster`）、命名空间（`Namespace`）、主题（`Topic`）、事件（`Event`）之间的关系与作用如下：
- 作用：
  - 租户：用于逻辑隔离不同客户或应用程序的数据。一个租户可以拥有多个命名空间、主题等。租户级别的隔离有助于确保数据的安全性和独立性
  - 集群：一组物理服务器，它们共同运行`Pulsar`服务，形成一个高可用的消息系统。在集群中，可以有多个租户，每个租户可以有多个命名空间和主题
  - 命名空间：`Pulsar`中的第二级实体，用于进一步组织主题。一个租户下可以有多个命名空间。如：可以将所有与订单相关的主题放在一个命名空间中，将所有与用户相关的主题放在另一个命名空间中
  - 主题：是消息的逻辑容器，生产者和消费者通过主题进行通信。一个命名空间下可以包含多个主题。主题可以是持久化的，也可以是非持久的
  - 事件：是实际的数据消息，它被生产者发送到主题中，并可以被一个或多个消费者接收和处理。每个事件都有一个唯一的 ID，确保了消息的顺序性和可追溯性
- 关系和结构
  - 关系
  - `租户 <-> 集群‌`：一个集群可以包含多个租户，而一个租户的数据通常分布在同一个集群中，但也可以跨多个集群进行配置以提高可用性和容错能力
  - `租户 <-> 命名空间`：‌一个租户下可以包含多个命名空间，这有助于逻辑上分隔数据
  - `命名空间 <-> 主题`：一个命名空间下可以包含多个主题，这有助于在逻辑上组织相关联的消息流
  - `主题 <-> 事件`：生产者将事件发布到特定的主题，而消费者从主题中订阅并消费这些事件
  - 结构
    ```text
    Cluster
     |
     +-- Tenant1
         |
         +-- Namespace1
         |   |
         |   +-- Topic1
         |   +-- Topic2
         |
         +-- Namespace2
             |
             +-- Topic3
             +-- Topic4
     |
     +-- Tenant2
         |
         +-- Namespace3
    ```
